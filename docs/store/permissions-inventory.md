# Android permissions inventory

## What was and was not verified

- `app.json` has **no** `android.permissions` and **no** `android.blockedPermissions`, so the build gets Expo's defaults.
- The repo has no `android/` directory (it is generated by `expo prebuild` in CI, .gitignore lists `android/`), and no built APK/AAB is here. **The final merged manifest could not be inspected.** The list below is reasoned from:
  - the installed libraries' own AndroidManifest.xml files in node_modules (read directly): expo-updates 0.25.28, expo-file-system, react-native-webview, expo-modules-core, expo-constants, expo-screen-orientation, expo-status-bar, expo-keep-awake, expo-font, expo-asset (these last ones declare no permissions);
  - Expo SDK 51's prebuild template, which (from my knowledge of SDK 51, NOT readable here since expo-template-bare-minimum is not installed) adds INTERNET, READ_EXTERNAL_STORAGE, WRITE_EXTERNAL_STORAGE, SYSTEM_ALERT_WINDOW and VIBRATE to the main manifest.
- **To verify**: build the AAB/APK and run `apkanalyzer manifest permissions app-release.apk` (or `aapt2 dump permissions`), or upload to Play internal testing and read Play Console -> App bundle explorer -> Permissions. Treat this document as a prediction until that is done.

## Inventory (predicted)

| Permission | Declared by | Why it appears | Does this game need it? | Recommendation |
|---|---|---|---|---|
| `android.permission.INTERNET` | Expo template; also expo-file-system | OTA update checks to u.expo.dev (App.tsx, expo-updates); asset download in expo-asset | **Yes**: needed for OTA updates. The game itself makes no network calls. | Keep |
| `android.permission.ACCESS_NETWORK_STATE` | expo-updates (verified in its manifest) | expo-updates checks connectivity before fetching updates | Yes, if OTA stays | Keep |
| `android.permission.VIBRATE` | Expo template | `navigator.vibrate()` in the WebView (src/util/haptics.ts, Settings "Vibration" toggle). The Web Vibration API needs the host app to hold VIBRATE | **Yes**: haptics feature | Keep |
| `android.permission.READ_EXTERNAL_STORAGE` | Expo template; expo-file-system (verified) | Legacy default for expo-file-system. Music is resolved by expo-asset (App.tsx `Asset.downloadAsync`) into the app's own cache directory, which needs no permission | **No** (inferred; confirm by testing music playback on a build with it blocked) | **Block** |
| `android.permission.WRITE_EXTERNAL_STORAGE` | Expo template; expo-file-system (verified) | Same | **No** (same inference) | **Block** |
| `android.permission.SYSTEM_ALERT_WINDOW` | Expo template ("draw over other apps", used by dev tools/overlay in debug) | No overlay is used by the game | **No** | **Block** (Play review flags it, users see "display over other apps") |
| `<package>.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION` | androidx.core (merged automatically) | Internal signature-level permission protecting non-exported dynamic receivers | n/a, harmless, app-private | Leave alone. Cannot be meaningfully removed |
| `com.google.android.gms.permission.AD_ID` | Would only be added by a library using Play Services Ads/Analytics | No such library in package.json | n/a | Not expected. If it shows in the merged manifest, block it and answer "no" to the Advertising ID declaration |
| `WAKE_LOCK` | Not declared by any installed expo module's manifest (expo-keep-awake uses window flags) | Not used | No | Not expected; if present, block |
| Camera / microphone / location / contacts / notifications (`POST_NOTIFICATIONS`) | Not declared | Not used | No | Not expected |

Orientation lock (expo-screen-orientation) and the WebView need no permission. The `mailto:` links open the user's email app via an intent and need no permission (no `<queries>` entry is needed for `Linking.openURL` on an unresolved scheme, but on Android 11+ package visibility can make `canOpenURL` false; the app uses `openURL` directly and catches failures, src/shell/navigation.ts).

## Recommended minimal configuration (do not apply to app.json from here; native change, needs a new build)

Add under `expo.android` in app.json:

```json
"blockedPermissions": [
  "android.permission.READ_EXTERNAL_STORAGE",
  "android.permission.WRITE_EXTERNAL_STORAGE",
  "android.permission.SYSTEM_ALERT_WINDOW"
]
```

Expected final list: INTERNET, ACCESS_NETWORK_STATE, VIBRATE (plus the app-private DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION).

Notes:
- `blockedPermissions` is an Expo SDK 51 `app.json` field that adds `tools:node="remove"` entries so the manifest merger drops those permissions even when a library adds them.
- This is a native change. Per MOBILE_GAME_DEV_RULES.md ("Android permission changes" are APK REQUIRED) and the runtime-version policy, it needs a new build and, because runtimeVersion follows `expo.version`, a version bump so older installs do not receive OTAs built for different native code (see release-track-plan.md).
- Test checklist after the change, on a real device with the new build: music plays and skips; sound effects; vibration on a trick; OTA check shows "Up to date" or downloads; bug-report email draft opens. If music fails with storage blocked, remove READ_EXTERNAL_STORAGE from the block list and re-test.
- Play Console: with only these permissions there is no Permissions Declaration Form to complete, and the Data Safety answers in data-safety.md hold.

## Other manifest items worth checking in the merged manifest (could not verify)

- `android:allowBackup` (Expo template default is true): decide intentionally (see data-safety.md section 5; setting is `android.allowBackup` in app.json).
- `android:usesCleartextTraffic`: should not be true in release.
- `targetSdkVersion`: Expo SDK 51 / React Native 0.74.5 builds target **34** (react-native's own manifest declares minSdk 23, targetSdk 34, read from node_modules). Play now requires **36** for new apps (see release-track-plan.md, blocker).
